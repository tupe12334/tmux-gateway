# Add Unix socket support for HTTP and gRPC servers

## Summary

Add Unix domain socket listeners alongside the existing TCP listeners for both the HTTP (REST + GraphQL) and gRPC servers. Unix sockets provide lower overhead for local-only communication and enable file-system-based access control.

The README has already been updated to document this feature. This issue tracks the actual implementation.

## Requirements

### New environment variables

- `HTTP_SOCKET` — Unix socket path for the HTTP server (optional; empty or unset = disabled)
- `GRPC_SOCKET` — Unix socket path for the gRPC server (optional; empty or unset = disabled)

### Server changes

- Read `HTTP_SOCKET` and `GRPC_SOCKET` from the environment at startup
- When `HTTP_SOCKET` is set, bind an additional Axum listener on the given Unix socket path (serving the same REST + GraphQL router)
- When `GRPC_SOCKET` is set, bind an additional Tonic listener on the given Unix socket path (serving the same gRPC service)
- Remove stale socket files on startup if they already exist
- Log the active socket paths at startup alongside the TCP addresses

### Expected behavior

```bash
# TCP only (current default, no change)
cargo run

# TCP + Unix sockets
HTTP_SOCKET=/tmp/tmux-gateway-http.sock GRPC_SOCKET=/tmp/tmux-gateway-grpc.sock cargo run
```

Clients can then connect via:

```bash
# REST
curl --unix-socket /tmp/tmux-gateway-http.sock http://localhost/ls

# GraphQL
curl --unix-socket /tmp/tmux-gateway-http.sock -X POST http://localhost/graphql \
  -H "Content-Type: application/json" \
  -d '{"query": "{ sessions { name windows created attached } }"}'

# gRPC
grpcurl -plaintext -unix /tmp/tmux-gateway-grpc.sock tmux_gateway.TmuxGateway/Ls
```
