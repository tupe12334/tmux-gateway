# Create AsyncAPI specification for async messaging interfaces

## Problem

The project has an OpenAPI 3.1.0 spec (`schemas/openapi.json`) documenting the REST API, a proto3 file for gRPC, and a GraphQL schema — but there is no AsyncAPI specification documenting the async/event-driven interfaces:

- **WebSocket** pane streaming (`GET /ws/pane/{target}`) — real-time pane content pushed to clients
- **gRPC server streaming** (`StreamPaneOutput` RPC) — server-side stream of pane output events
- **GraphQL subscriptions** (`paneOutput(target, intervalMs)`) — subscription-based pane event streaming

These async channels are a core part of the gateway's value proposition but are undocumented in a machine-readable async API format.

## Proposed solution

Add an AsyncAPI 3.0 specification file at `schemas/asyncapi.json` (or `.yaml`) that describes:

1. **WebSocket channel** — `/ws/pane/{target}` with message schema for pane output frames, including the configurable polling interval query parameter
2. **gRPC streaming channel** — `StreamPaneOutput` RPC with `StreamPaneOutputResponse` message schema
3. **GraphQL subscription channel** — `paneOutput` subscription with event payload schema

The spec should reuse domain types already defined in the OpenAPI spec where possible to stay DRY.

### Nice to have

- Auto-generate the AsyncAPI spec at build time (similar to how OpenAPI is generated via utoipa)
- Validate the spec in CI

## Acceptance criteria

- [ ] AsyncAPI 3.0 spec file exists in `schemas/`
- [ ] WebSocket pane streaming channel is documented with message schema
- [ ] gRPC streaming RPC is documented
- [ ] GraphQL subscription is documented
- [ ] Spec validates against the AsyncAPI 3.0 JSON Schema
